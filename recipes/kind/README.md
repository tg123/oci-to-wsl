# Recipe: `kind` — Kubernetes in WSL2

Imports the [`kindest/node`](https://hub.docker.com/r/kindest/node) image into a
**systemd-enabled WSL2 distribution** and brings up a **single-node Kubernetes
control plane** that runs natively in WSL — no Docker daemon and no nested
containers on the Windows host.

## What you get

- A WSL distro named `kind` booting systemd.
- containerd + kubelet + a `kubeadm`-initialised control plane.
- The control-plane node untainted (so workloads schedule on it) and a CNI
  installed, so the node reaches `Ready`.
- An admin kubeconfig at `/etc/kubernetes/admin.conf` inside the distro.

## Launch

```powershell
# The recipe stages bootstrap-kind.sh next to the profile, so allow fetching
# relative files[].src from the same URL:
$env:OCI_TO_WSL_PROFILE_FOLLOW_URL = '1'

oci-to-wsl.exe --profile https://raw.githubusercontent.com/tg123/oci-to-wsl/main/recipes/kind/profile.yaml
```

From a local clone (no env var needed — the script is resolved next to the
profile on disk):

```powershell
oci-to-wsl.exe --profile .\recipes\kind\profile.yaml
```

`init_cmds` run the bootstrap automatically, so when the command returns the
cluster is ready.

## Using the cluster

Inside the distro:

```powershell
wsl -d kind -- bash -lc 'export KUBECONFIG=/etc/kubernetes/admin.conf && kubectl get nodes -o wide'
```

To reach the API server from the Windows host, export the kubeconfig and point
its `server` at the WSL VM's IP (the kubeconfig generated by `kubeadm` uses the
in-distro address):

```powershell
wsl -d kind -- cat /etc/kubernetes/admin.conf > $env:USERPROFILE\.kube\kind.config
```

> .NET Framework / older TLS stacks that can't supply a custom CA may need
> `insecure-skip-tls-verify: true` in place of `certificate-authority-data`
> (ephemeral local clusters only).

## How it works

WSL boots the image's systemd directly instead of running it as a Docker
container, so [`bootstrap-kind.sh`](bootstrap-kind.sh) reproduces what kind's
container entrypoint normally does: fixes mount propagation, creates
`/dev/kmsg`, sets networking sysctls, configures containerd with the `cgroupfs`
driver, patches out the kind kubelet drop-in that assumes a Docker cgroup
namespace, runs `kubeadm init`, untaints the node, and installs a CNI. The
script is idempotent, so re-importing or re-running it is safe.

## Pinning the Kubernetes version

`profile.yaml` pins `image: kindest/node:v1.32.2`. Change that tag to target a
different Kubernetes version (use a tag published for the
[kind release](https://github.com/kubernetes-sigs/kind/releases) you want).

## Requirements

- Windows with **WSL 2** (systemd support; Windows 11 or Windows Server 2025).
- Enough RAM/CPU for a control plane (≈2 vCPU / 2 GiB is a practical minimum).
